# HID Hackathon - Face Liveness & Identity Kiosk

Decides **ALLOW / REQUEST VERIFICATION / DENY** from a ~1 s webcam burst, in well under 2 s.
Everything runs locally on CPU with pretrained models; identity can be switched to Amazon Rekognition later.

## Run

**Windows: double-click `start.bat`.**
- **First run:** it creates `.venv`, installs the packages, downloads the models (~450 MB including the one-time PyTorch install for the export) and exports MiniFASNet to ONNX.
- **Every run:** it starts the server and opens http://localhost:8000.
- **Stopping:** press Ctrl+C or close the window.
- **Options:**
  - `set PORT=8010` before running uses another port.
  - `set NO_BROWSER=1` stops it opening the browser.
  - Deleting `.venv\.installed` forces a package reinstall.

Manual equivalent:

```bash
py -3.12 -m venv .venv
.venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python scripts/get_models.py
.venv/Scripts/pip install torch onnx --index-url https://download.pytorch.org/whl/cpu
.venv/Scripts/python scripts/export_minifas_onnx.py
.venv/Scripts/python -m uvicorn app:app --app-dir backend --port 8000
```

Open http://localhost:8000 in Chrome or Edge, which need camera access.

There are two separate apps:

| App | URL | Who sees it |
|---|---|---|
| **Kiosk** | `/` | Everyone. Face recognition and the access decision only, with no links to the back office. |
| **Admin console** | `/console/` | Admins only. Its own sign-in screen (face check or email, then authenticator code). |

Roles: **student, staff, contractor, visitor** use the kiosk only, with door access set by the schedule.
**admin** is one extra built-in role: every door at any time, plus every console page and power.

| Console page | Purpose |
|---|---|
| `/console/enroll.html` | Guided enrollment, roles (including Admin), access expiry, emails, authenticator QR codes |
| `/console/policy.html` | Access schedule matrix, editing, "test a decision" tool |
| `/console/audit.html` | Hash-chained decision log, sync status, chain integrity |
| `/console/record.html` | Record labelled test clips for the evaluation |
| `/console/report.html` | Results: **Run evaluation** replays every clip and computes the metrics |

**First run:** until an admin exists, `/console/enroll.html` is open. Enroll yourself with the role Admin and your email, then scan the QR code.
After that only admins can enroll people or make someone an admin. Adding or removing an admin needs a fresh face check, and the last admin can't be removed.
**No duplicates:** enrollment is refused if the user ID already exists or the face already belongs to someone enrolled (emails are unique too).
Signed-in admins also get the demo controls on the kiosk: zone, demo clock, network-loss simulation and signals.

## Secure access beyond liveness

### Context-aware access control
A live, matched face is not enough on its own: every decision is checked against the campus schedule in `backend/access_policy.yaml`. The schedule defines roles × zones × weekly windows, a grace period, holidays and high-security zones. Each person has a role and an optional access-valid-until date.

| Biometrics | Schedule | Online | Offline |
|---|---|---|---|
| Live + match | Inside window, standard zone | **Allow** | Step-up (authenticator code) |
| Live + match | Grace period, or high-security zone | Step-up (SMS or authenticator) | Grace: step-up · High security: **Deny** |
| Live + match | Outside window, no zone access, expired, holiday | **Deny** | **Deny** |
| Spoof or no match | Not checked | **Deny** | **Deny** |

The kiosk has a zone selector and a demo clock. The **Policy** page shows the schedule matrix and has a "test a decision" tool.

### Offline fail-safe mode
- **Roles:** the AWS server runs as the **central** node (`HID_NODE=central`). A kiosk laptop runs as an **edge** node (`edge.bat`, generated by `deploy.bat edge`).
- **The edge runs the whole app on the laptop** (`http://localhost:8000`), so it keeps working with no internet. The AWS-hosted site itself can't work without a connection; its "Simulate network loss" button only demonstrates the offline rules.
- **People sync:** while online, the edge copies everyone enrolled on central every 30 s and on reconnect. That covers their details, role, authenticator secret and face templates, but no photos. The copy is stored encrypted, and people removed on central are removed from the edge too.
- **Connection check:** the edge checks the central server every 4 s. A "Simulate network loss" button is also available for demos.
- **When central is unreachable, the kiosk never fails open:**
  - Liveness still runs on the device.
  - Identity uses the on-device face-template cache (no images, expires after 7 days).
  - Every entry needs a code from an authenticator app (TOTP), which works with no network.
  - High-security zones close.
- **Audit:** each decision is appended to a hash-chained audit log. It holds decision metadata only, with **no raw biometrics**.
- **Sync:** queued records sync to central automatically when the connection returns. Ingest is idempotent, and any record whose hash doesn't match is rejected. The **Audit** page shows the records and whether each chain is intact.

### Data protection
- **Encrypted at rest** (AES with an HMAC integrity check, via Fernet, in `backend/vault.py`): face templates, enrollment face photos, recorded test clips, authenticator secrets and phone numbers. Data from older versions is encrypted automatically at startup.
- **The key is never stored with the data**, so a copied `data/` folder is unreadable:
  - **Windows kiosk:** the key is sealed with Windows DPAPI, so only the same Windows account on the same machine can open it.
  - **AWS server:** the key is generated on the server and kept in its root-only settings file, outside the data folder. It never leaves the instance.
- If the key doesn't match the data, the app refuses to start rather than running half-broken.
- **In transit:** HTTPS between the browser and CloudFront, and HTTPS for edge-to-central sync, which also needs a shared key. The people list is also encrypted end to end with a key derived from the sync key, so even the CloudFront-to-server hop only sees ciphertext. The server's app port only accepts traffic from CloudFront and the deployer's IP.
- **Not stored at all:** no raw images in the audit log, and recovery codes are kept only as hashes.

## Amazon Rekognition (cloud identity)

Face matching can use Amazon Rekognition instead of the local ArcFace model. Liveness always runs locally.

1. Copy `aws-credentials.example.bat` to `aws-credentials.bat`. It is git-ignored, so it never gets committed.
2. Get the values from the Workshop Studio event page: **Get AWS CLI credentials**, then the **Windows** tab. They expire after a few hours, so paste fresh ones when Rekognition stops working.
3. Run `start.bat`. It loads the credentials, sets `HID_IDENTITY=rekognition` and checks access.
4. Push people who are already enrolled into the collection, so they don't need to re-enroll:
   ```bash
   .venv/Scripts/python scripts/sync_rekognition.py
   ```

How it works:
- **Collection:** `hid-kiosk-faces` in `us-east-1`. Each person has 3 indexed faces.
- **Matching:** the best frame is cropped and searched with `SearchFacesByImage`. That call runs in parallel with the liveness checks, so it adds little to the decision time.
- **Thresholds:** `identity.rekognition` in `backend/config.yaml`, with match ≥ 0.90 and borderline ≥ 0.75.
- **If AWS is unreachable,** the kiosk answers REQUEST VERIFICATION ("identity service unavailable") instead of crashing.

## Evaluation

1. Enroll each tester.
2. On `/console/record.html`, record ~6+ clips per label per person. For attacks, set **Subject** to the person shown in the photo, screen or mask.
3. Press **Run evaluation** on `/console/report.html`, or run `.venv/Scripts/python eval/run_eval.py`.

The report shows:
- **Headline metrics:** liveness detection accuracy, face authentication accuracy, FAR, FRR and decision time.
- **Per attack type:** APCER, BPCER and ACER (ISO/IEC 30107-3).
- **Decision breakdown:** what the system decided for each scenario, plus a latency histogram.
- **Ablation:** how well each check separates live from attack on its own (AUC).
- **Threshold sweeps:** for calibrating `backend/config.yaml`.

Every rate includes a 95% confidence interval, because the test set is small.

## Pipeline

1. **Capture**: 10 frames over 1 s, sent as JPEGs.
2. **Detect + landmarks + quality**: YuNet face box, then MediaPipe 478-point mesh, blendshapes and head pose.
   - Quality checks: blur, brightness, face size, pose, multiple faces.
3. **Liveness**, each check scored 0-1:
   - **MiniFASNet V2 + V1SE** (pretrained anti-spoof CNNs)
   - **Flatness**: optical-flow tracks inside the face. If one homography explains all the motion, the face is a flat photo or screen.
   - **Moire**: whitened FFT spectrum peaks, which come from a screen's pixel grid.
   - **Glare**: saturated specular pixels.
   - **Blink**: a bonus only.
4. **Identity**: ArcFace `w600k_r50` cosine similarity, 1:N or 1:1 with a badge.
5. **Fusion** (`backend/config.yaml`): a weighted liveness score plus hard vetoes, then:
   - ALLOW: live and matched
   - DENY: spoof, veto, no match, or a failed challenge
   - REQUEST VERIFICATION: borderline
6. **Verification flow**:
   - First, a random one-time challenge (blink, turn left or turn right).
   - If still borderline, a mock OTP sent to the enrolled phone. It appears on the "demo phone" panel.
